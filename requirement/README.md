# Requirement Directory

This directory contains project requirements that should be reviewed and improved before implementation. Requirements here are intentionally structured as living source documents, not final implementation notes.

## Sections

- [Design Requirements](./design/README.md): shared product design foundations, component contracts, and review checkpoints.

## Requirement Rules

- Requirements define what must remain stable across the product.
- Pages should assemble approved components instead of inventing new UI patterns.
- New design decisions must update the relevant foundation or component document before implementation.
- Unresolved decisions should remain visible as open questions, not hidden in implementation work.

## Review Flow

1. Draft the requirement.
2. Mark assumptions and open questions.
3. Review brand, accessibility, responsive behavior, and component coverage.
4. Promote stable decisions into implementation-ready requirements.
5. Use component contracts as the basis for page assembly.
