# Visual Direction

Status: `Draft`

## Product Feel

AgentMS should feel trustworthy, structured, current, and practical. It should not feel like a marketing site, a property management suite, or a payment product.

## Palette

Use a restrained neutral base with two functional accents:

- Primary action: deep teal for search, publish, verify, and save actions.
- Freshness/trust: green and amber status colors for current, stale, pending, and risk states.
- Moderation/danger: red only for reports, rejection, suspension, and destructive actions.

Avoid a one-note blue, purple, beige, or decorative gradient theme.

## Layout

- Public pages prioritize search, comparison, and trust signals.
- Student pages prioritize saved context and inquiry state.
- Agent pages prioritize operational task flow, listing freshness, and follow-up.
- Admin pages prioritize queues, evidence, status, and accountable decisions.

## Component Direction

Use the components in `requirement/design/component-inventory.md`:

- App navbar and role sidebar.
- Search and filter bars.
- Listing cards and listing detail panels.
- Agent profile cards.
- Status badges and freshness indicators.
- Data tables with row actions.
- Forms for auth, profile, listing, verification, and locations.
- Confirmation modals for destructive or high-impact actions.

## Status Language

Availability:

- `Available`
- `Limited`
- `Full`
- `Unavailable`

Freshness:

- `Confirmed today`
- `Confirmed this week`
- `Needs refresh`
- `Stale`

Agent verification:

- `Unsubmitted`
- `Pending`
- `Verified`
- `Rejected`
- `Suspended`

Inquiry state:

- `New`
- `Contacted`
- `Viewing Scheduled`
- `Negotiating`
- `Closed Won`
- `Closed Lost`
- `Spam/Invalid`
